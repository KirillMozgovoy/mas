# Лабораторная работа №1 · Теория многоагентных систем

**Тема:** спецификация и архитектурное проектирование многоагентной системы распределения заказов между курьерами.

**Автор:** Мозговой Кирилл Сергеевич, группа Б24-517.

## Описание

Система моделирует распределение и выполнение заказов на доставку. Источник передаёт заявки диспетчеру, диспетчер выбирает исполнителя, а три курьера с разной скоростью и грузоподъёмностью принимают или отклоняют назначения и выполняют доставку. Агенты взаимодействуют через сообщения; журнал обмена сохраняется вместе с результатами моделирования.

В работе описаны роли, состояния, полномочия агентов и протокол взаимодействия, приведены диаграмма ролей и граф коммуникаций. Исполняемый прототип иллюстрирует разработанную архитектуру.

Скачайте репозиторий через **Code → Download ZIP**, распакуйте архив и откройте `lab1/demo/index.html` в браузере. Интернет и Python для просмотра не требуются.

## Запуск симуляции

Требуется **Python 3.10+**. Сторонние библиотеки для симуляции и тестов не нужны.

Из корня репозитория перейдите в папку лабораторной:

```sh
cd lab1
```

Выполните нужный сценарий:

```sh
python src/simulation.py --scenario normal --output demo/normal.json
python src/simulation.py --scenario overload --output demo/overload.json
python src/simulation.py --scenario capacity --output demo/capacity.json
```

В Linux вместо `python` может потребоваться `python3`.

| Сценарий | Условия |
| --- | --- |
| `normal` | 6 заказов, поступающих в такты 0–4 |
| `overload` | 18 заказов в такт 0; дедлайн каждого — такт 10 |
| `capacity` | 6 обычных заказов и заказ HEAVY массой 9 при максимальной грузоподъёмности курьера 6 |

По умолчанию используется политика `nearest`: минимальная оценка времени маршрута среди свободных курьеров с подходящей грузоподъёмностью. Параметр `--policy round_robin` включает циклическое назначение.

Запуски детерминированы. Параметр `--horizon 120` задаёт предел моделирования. Невыполнимый заказ остаётся в состоянии `waiting` и не блокирует выполнение остальных.

## Проверки

Из папки `lab1`:

```sh
python -m unittest discover -s tests -v
```

Пять тестов проверяют завершение выполнимых сценариев, единственность назначения, ограничение массы, обработку повторных сообщений, отказ занятого курьера, изоляцию невыполнимого заказа, детерминизм и причинный порядок событий.

## Условности и ограничения

Модель использует дискретное время, манхэттенское расстояние и один заказ на курьера. Движение выполняется сначала по x, затем по y; погрузка и выгрузка имеют нулевую длительность. Дедлайн задаёт желательное время доставки, опоздание не отменяет заказ.

Агенты работают в одном процессе и обмениваются сообщениями через надёжную FIFO-шину. Сетевые задержки, потери сообщений и отказы агентов не моделируются. В репозитории реализована ЛР1; исследования распределения, конфликтов и надёжности для ЛР2–ЛР4 пока не выполнены.
